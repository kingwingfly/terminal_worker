## Architecture contract

The [README architecture](README.md#client-os-and-remote-services) and #44 define the target; the [architecture contract](docs/architecture/contract.md) records the decisions the steps follow. Keep current limitations explicit; do not describe planned features as implemented.

- Each OS instance owns its client kernel, local process/signals/descriptor/VFS/mount namespace semantics, IPC, devices, resource accounting, PID 1 and sessions. Remote service adapters supply authenticated filesystem, identity, device/execution, relay and dispatch contracts. Cloudflare is the first provider; local syscalls and remote protocols are separate interfaces.
- Instance, execution host, account, login session and app window are distinct identities. A fresh boot creates an instance; additional pages attach only explicitly where supported. Sharing an account, cookie or remote volume does not merge kernels or namespaces. A new instance uses an immutable template with fresh runtime/credentials, not another user's live memory or secrets.
- Boot: browser boot program verifies kernel/initial filesystem → kernel creates the initial root and executes early `/init` as PID 1 → early userspace establishes bootstrap transport/authentication and assembles `/sysroot` plus required devices → root switch and exec main init, retaining PID 1 → system/login services → account or distinct guest session → shell or compositor/desktop/apps. Include root clients/recovery tools in the initial filesystem. Systemd is a lifecycle reference; upstream systemd/unit-file compatibility is not claimed.
- `xtask` assembles/verifies boot artifacts. Wrangler deploys them. Cargo features select compiled capabilities; service/mount configuration controls startup. `/boot` contains release and early-userspace references, never user data or private signing keys.
- Separate source/device, filesystem instance, inode, open description, mount attachment, namespace and export. L1 supplies stable identity, persistent ownership/modes/ACLs/xattrs, actual flush semantics and declared cross-client consistency. L2 uses one mount model for root/images/special filesystems/providers, including busy unmount, lazy detach and revocation as distinct operations.
- L2 must implement actual `chroot`: syscall/runtime ABI plus ordinary command, per-process root/cwd/mount context, physical path and executable lookup, privilege/errno, fork inheritance and exec preservation. The syscall does not chdir, close fds or create namespaces; the utility changes to its new root then execs. Outside cwd/retained fds keep their documented semantics within original grants. Chroot alone is not a sandbox or the boot root-switch operation.
- Host folders and browser storage expose existing filesystem trees without directory copying. Multiple attachments need stable shared identity/metadata. Virtual block images and `mkfs` are separate future features; mounting a tree must never format it.
- Filesystem exports are userspace VFS services. Account ACLs or export-scoped passwords define access; receivers explicitly mount. Local IPC, P2P and relay must enforce identical authority, lifetime, cancellation and uncertain-write rules. Shared cloud paths generally need ACLs instead of re-export. A live export needs its host; a relay does not provide storage replication.
- Userspace compositor owns display/input and surface isolation. Desktop-shell panel/background/launcher roles are explicit. Files, Terminal, Mounts, Editor and Preview become ordinary supervised OS processes in L6; Terminal launches a separate shell through a PTY. Portable controllers/services remain outside rendering; browser/native display, input, picker, clipboard, IME and accessibility belong to host adapters.
- Preserve archive/media acceleration through typed devices: execute near granted cloud data, stream bulk bytes through authorized storage gateways, and return status/results. Logical boot-distribution and resource/acceleration roles may share a deployment. General CPU/GPU placement is later explicit task work, with capability/privacy/consent/quota/cost constraints; no arbitrary program is automatically distributed by name.
- Provider adapters translate versioned OS contracts into backend APIs and enforce the resource authority. They must advertise/reject unsupported filesystem/runtime guarantees honestly. Reusing path/permission code on a server is valid. Client root, pathnames, digests, instance IDs and claimed PIDs never grant remote administrator authority.
- L0 defines a portable dispatch contract; Phase 9.2-Q implements Cloudflare Queues after the task foundation. Durable task state/outbox, idempotency, attempt leases/fencing, recoverable handoff, cancellation/revocation, bounded retries/DLQ and fairness remain task-service responsibilities. Queue messages contain scoped references, not bulk bytes or provider account secrets. Keep interactive VFS, PTY/signals, GUI and media on direct/streaming paths. No Queues infrastructure is configured today.
- Virtual NIC/socket stack, additional cloud/OpenDAL adapters, native CPU execution and GPU/shared-storage backends retain separate gates. Browser transports do not imply raw TCP/UDP. The headless native CPU agent is a Phase 9 deliverable; a desktop wrapper alone does not provide an executor.

## Current implementation and required preservation

- L1a parts 1–2 (`crates/vfs`, `os-vfs`) provide the portable handle-based trait, open descriptions, descriptor table, reference tmpfs and portable cloud driver. The Worker serves `/api/fs` v2 and `/api/fs/data`: instance-bound signed handles, per-call process credentials, durable session/open/lock state, cancellable open tickets and streamed immutable byte extents. See [cloud protocol](docs/architecture/cloudfs.md). Renew the two-minute service lease and drain deferred cancellations/releases; a disconnected transport must retain cleanup work. Browser syscalls still use the path protocol: host HTTP transport, client/process-table integration, other adapters and the L1 conformance/latency gates remain later parts of #48.

- Each tab's dedicated client-kernel Worker owns process Workers, SAB pipes/terminal buffers and private providers. SharedWorker is optional infrastructure without process state. `Machine` still supplies server process registration/admission, login/init coordination and registry resource policy; `OsAuthority` projects the shared filesystem and authorizes resources. Replace these boundaries with proof/lifecycle and denial tests, not by simply deleting authorization; no compatibility window or data migration is needed (see Delivery priority).
- Installed `/usr/bin/init` is a restricted WASI PID 1 orphan reaper. `/usr/bin/supervise` is ordinary userspace with validated units, dependencies/readiness, timeouts, bounded retries/journals and descendant cleanup. Host/session orchestration still owns startup. A full early-init/root-switch service graph remains L3 work.
- Signed base/sysext/confext compositions, generation-pinned artifacts/credentials, root-only image activation and compatible rollback exist. Activation does not migrate live processes or downgrade the database. Private extensions do not obtain installation trust or privileged-service access.
- Standard commands are executable WASI/WASIX programs. uutils applets and `crates/utilities` use the same loader/process path from the browser shell and dash. Command logic belongs in userspace; add reusable kernel/device primitives rather than command-specific privileged routes. `/dev/archive` and media clients use typed ioctl/task lifecycles. `Wait` reports process lifecycle, not archive output.
- Mounts has Mounted, Add mount, Connect and Publish panes. Host folder prefers a browser directory handle; only unsupported capability offers `os-local-helper`. Picker cancellation/denial does not switch source. Browser storage mounts `os-workspace` directly. The helper supports Linux `openat2`, not native program execution or arbitrary host access.
- Provider permissions currently use a per-mount overlay that resets private on remount. Alias metadata/flush/unmount behavior still differs from the target; #44 must fix it. Current source bytes stay in place. Private mounts are scoped to their host/login workspace, and cloud delegation is separate.
- Exports use verified OS accounts, supplementary groups, VFS ACLs, optional scoped passwords, explicit receiver consent and bounded relay/P2P connections. Passwords map to publisher access only inside the export. Creation currently uses publisher ownership/default ACLs; L1/L4 must define and test the final identity rules. ACL changes/revocation apply to existing connections. Only an unacknowledged file-changing request warrants an uncertain-write warning.
- Built-in GUI apps currently share Leptos/DOM frontend state. Keep Files Refresh/F5, cached-metadata invalidation, back/forward scroll, explicit mount consent, active-line completion and wrapped-prompt input placement when extracting portable controllers. Closing Mounts does not unmount.

## Security and data invariants

- The service authenticates every resource operation, including HEAD, Range, conditional responses and executable reads. Public routing headers, Web Lock names, numeric IDs and client-reported hashes are not credentials. Process tokens authorize only their recorded lineage/namespace/rights; account changes cannot rewrite running process identities.
- Current process credentials preserve umask/cgroup/generation and descriptor ownership through fork/exec. A fork waits for registry admission before guest code starts. Shared open descriptions retain offsets/flags and counted holders; killed processes release holders before parent wait completion. Exec races must not revive revoked tokens; revocation retries remain durable.
- Root still needs an executable bit. Uploaded setuid/setgid metadata does not elevate. Executable-only reads are scoped to execution; they do not grant general read access. Local kernel privilege cannot bypass remote service checks or the host picker/helper ceiling.
- VFS checks cover ancestor traversal, correct owner/group/other selection, named/default ACLs, sticky directories and protected links. Creation uses creator credentials, requested mode, umask/default ACL and setgid inheritance. Keep permission behavior in shared filesystem rules and service authorization, not DOM handlers.
- Filesystem metadata decisions and commits use synchronous authority transactions; never await inside one. Async work occurs outside, followed by revalidation. Bulk file bytes stream through authorized Worker/R2 gateways, not through the authority's WASM/SQLite path. Commit checks the original destination/revision and immutable chunk identity.
- Retained descriptors refer to their own inode/content, not whatever replaces their pathname. Copy/clone content sharing does not merge inode permissions. Garbage collection must respect open/job/image references and active generations. Keep archive output deterministic and reconcile retries before committing results.
- `.dev.vars`, `.local-password` and `.wrangler` contain private local state. Never print/commit secrets. `ADMIN_PASSWORD` initializes root once; do not reset everyday credentials for tests. `SESSION_SECRET` is the password pepper and must be restored with data. R2 alone is not a filesystem backup; preserve authority tables, bytes and credentials together.
- The current state schema is 8; incompatible older schemas are refused. During #44, schema, Durable Object classes and storage layout may change without migration (see Delivery priority); bump the schema version with each incompatible change. Cloudflare still requires wrangler `[[migrations]]` entries for Durable Object class changes, in deployment and local development; the redeploy may start a fresh history. Browser-side stores (OPFS, IndexedDB, preferences) survive the redeploy, so each carries a format version and is reset, never misread, when it differs; file contents are never deleted by a reset. Never attach an empty unrelated authority to an initialized bucket.
- Device/task cancellation follows declared ownership. Attached work ends when its final owning descriptor closes; explicit authorized detach has its own deadline/recovery policy. Durable dispatch must not silently detach work or revive expired grants.

## Account behavior

These are current behaviors. A #44 change to them needs a deliberate decision and denial tests rather than an accidental UI/API change; no migration of existing accounts or sessions is needed.

- Individual signed-out identities are `guest-<id>` in group guest, uid 1,000,000–1,999,999. Use `is_guest_id`; reserved uid/gid 65534 is the fallback/group. Shared `/guest` is sticky; `useradd -m` creates a private home.
- Guest cannot sudo; ordinary sudo callers need wheel membership, rechecked for explicit requests. `sudo COMMAND` elevates that command only; the credential cache lasts five minutes. `su` uses the target password except for authorized root switching. Current `sudo -u USER` switches the browser account without accepting a trailing command.
- Logout/exit revokes the browser session and returns to guest without a nested account stack. Existing process snapshots remain separate; explicit login shutdown is a different lifecycle operation. Locking/account changes revoke old sessions; unlocking never revives them.
- `passwd --force` skips the minimum length only; the password must remain nonempty and within 512 bytes. Permission failures never implicitly sign in as root.
